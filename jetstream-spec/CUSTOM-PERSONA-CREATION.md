# CUSTOM PERSONA CREATION SPEC

Player can create custom personas with the same schema as canonical personas. Two creation modes.

## MODE 1: GUIDED CREATION (recommended default)

Player provides minimum info via form. Claude (Sonnet, one-time call) generates the rest.

### Form fields (player provides):
1. **Display name** (required): "Naia Reyes"
2. **Age** (required): 25-80 (slider)
3. **Gender** (required): dropdown — man / woman / non-binary / custom (text input)
4. **Pronouns** (required): dropdown — he/him / she/her / they/them / custom
5. **Public orientation** (required): dropdown — straight / gay / lesbian / bisexual / pansexual / queer / asexual / custom
6. **Region** (required): text — "Mexican-American (Los Angeles)"
7. **Home base ICAO** (required): autocomplete from airports.json
8. **Wealth tier** (required): 1-5 slider with labels
9. **Short description** (required): 1-2 sentences. "Indigenous Mexican-American climate scientist who runs a private foundation for Indigenous land rights."
10. **Relationship to player** (optional): dropdown — friend from college / ex / met at a party / business contact / hookup / family friend / introduced by [persona] / no prior connection

### Auto-generated by Claude (single Sonnet call):
- `voiceStyle` (sentence describing how they talk)
- `background` (3-5 sentence bio)
- `interests` (3-6 items)
- `tastes` ({drinks, wears, drives})
- `playerDynamic` (how they engage with player based on relationshipToPlayer + identity)
- `drama` (current life situation, 1-2 sentences)
- `currentPartners` (empty unless prompted)
- `monogramColors` (deterministic hash from name)
- `fleet` (1-2 plausible aircraft for wealth tier)
- `preferredResorts` (3-5 IDs from existing resorts.json based on profile)
- `residences` (1-3 plausible based on region)

### LLM call structure:
```typescript
async function generateCustomPersona(seed: CustomPersonaSeed): Promise<Partial<Persona>> {
  const provider = getRegistry().getDefault();
  const response = await provider.complete({
    systemPrompt: `You are creating a character profile for a luxury social simulation game. 
The player provides basic info; you fill in the rest with cohesive, specific, evocative detail. 
Match the tone of canonical personas (specific tastes, real brands, named places, identifiable voice patterns). 
Output ONLY valid JSON matching the schema.`,
    messages: [{
      role: 'user',
      content: `Generate a persona profile based on:
${JSON.stringify(seed, null, 2)}

Output JSON with these fields:
- voiceStyle (string, 1-2 sentences)
- background (string, 3-5 sentences)
- interests (string array, 3-6 items)
- tastes (object with drinks, wears, drives strings)
- playerDynamic (string, 2-3 sentences)
- drama (string, 1-2 sentences)
- residences (string array, 1-3 items)
- preferredResorts (string array of resort IDs from this list: [list provided])
- fleet (array of {tailNumber, model, status})

Match the wealth tier: tier 5 = billionaire dynasty/exit, tier 4 = high net worth (~$500M-$2B), tier 3 = ~$50-500M, tier 2 = ~$5-50M, tier 1 = under $5M.`
    }],
    maxTokens: 1500,
    temperature: 0.9,
    model: 'claude-sonnet-4-6',  // explicit Sonnet for creation, Haiku for ongoing DMs
    metadata: { purpose: 'custom-persona-bio' }
  });
  
  return JSON.parse(response.content);
}
```

### Confirmation step:
After Claude returns generated fields, show them to player in editable preview:
- Player can edit any field
- Player clicks "Create" to save
- Persona inserted into `db.personas` with `isCustom: true`, `createdBy: 'player'`, `createdAt: now`

---

## MODE 2: ADVANCED CREATION

Power-user mode. Player fills in everything manually. Same form but all fields editable, no LLM generation.

Same persona schema, just no auto-fill.

---

## EDITING / DELETING

- Custom personas can be edited at any time via persona detail page → "Edit" button
- Custom personas can be deleted (confirmation modal: "This will remove [name] permanently")
- Canonical personas (non-custom) cannot be edited or deleted (could optionally allow editing for power users; default disable)

## PORTRAIT GENERATION

Custom personas use monogram fallback by default. If player wants imagery:
- "Generate Portrait" button on detail page
- Calls Imagen via existing `generate_imagery.js` logic, scoped to single persona
- Saves to `/public/portraits/{personaId}.jpg`
- Updates persona record with imageUrl

## COST DISCLOSURE

Show in UI: "Generating with Claude Sonnet ~$0.05" before creation.
Custom persona creation logs to apiUsage as `purpose: 'custom-persona-bio'`.

## ROUTING

- `/social/custom/new` — creation form
- `/social/[personaId]` — detail page (works for custom too, with edit/delete buttons visible)
- `/social/custom` — list of player's custom personas

## EDGE CASES

- Player tries to use ICAO not in airports.json → autocomplete prevents
- Player creates persona with name colliding with canonical → require unique displayName, suggest variation
- Player tries to create 50+ custom personas → soft warning at 20, hard cap at 100 (cost concern)
- LLM generation fails → fallback to manual mode with note "Auto-fill unavailable, please complete manually"
- Player creates persona, goes back to map → new persona seeded at their homeBase ICAO with empty relationship
